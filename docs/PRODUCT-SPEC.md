# 产品规格：从云端执行验证到可用的异步工作台

> 版本：v0.1 · 日期：2026-09-17
> 上位文档：[PRODUCT-PLAN.md](PRODUCT-PLAN.md)
> 本文定义首个可用版本的用户行为、系统契约、技术目标与发布验收，不描述当前已具备的能力。
> 数值是供开发和容量验证使用的初始工程目标，不是已测数据、开发耗时预测或对外 SLA。首轮基线测试后需复核并记录调整原因；产品收益指标须经实际试用校准。

> 规范开发前先执行 [10 天验证冲刺](VALIDATION-SPRINT.md)。验证冲刺允许使用明确披露限制的单节点原型，只用于证明链路、体感与边界，不代表满足本文 V0/V1/V2、安全底线或故障矩阵。继续开发时，以冲刺证据复核本文假设和数值。

## 1. 可用版本的定义

**用户能够把一件边界明确的工作交给云端，关闭电脑，在另一设备上处理必要决策，最后取得可验收的结果。全过程不需要自己维护服务器或盯守执行。**

验证版只证明“云端能跑”；可用版还必须证明：

- 用户知道何时可以放心离开。
- 断线、重启和等待不会让工作丢失或失去控制。
- 不需要用户频繁补指令才能向前推进。
- 任务状态可信，结果可取回，异常可处理。
- 操作有授权，资源有上限，用户可以停止后续工作。

多 bot 不是本规格的前提或交付门槛。执行内核继续复用 VCoder 与 skills/子 agent。

### 1.1 首发范围

首发仍采用待验证的窄场景：个人开发者委派一个 Git 仓库内的有限变更，云端交付补丁、修改文件及测试证据。

| 首个可用版本必须覆盖 | 暂不要求 |
| --- | --- |
| 一种仓库接入方式、明确的输入快照 | 任意本地环境自动迁移 |
| 一个账号下独立任务与工作空间 | 完整组织角色体系、多人实时编辑 |
| 云端执行、断线重连、跨设备查看 | 原生移动 App、全平台桌面打包 |
| 决策通知、审批、停止、交付下载 | 自动发布和无限权限操作 |
| 故障恢复、预算、数据删除、审计 | 大规模多租户和多 bot 调度 |

多个试点用户上线前必须具有用户间隔离，不能用“不做组织管理”作为共享凭据或数据的理由。

### 1.2 三项用户目标与验收锚点

| 编号 | 用户目标 | 可观察证据 |
| --- | --- | --- |
| G1 | 离开设备 | 任务确认接收后发起电脑关机，工作仍完成；另一设备可取回结果 |
| G2 | 释放注意力 | 普通任务不要求中途补指令；必要决策集中、可操作；无需反复读日志 |
| G3 | 放心委派 | 知道操作范围、预算和状态；随时可停止；故障后不会默默丢失或重复高风险动作 |

减少跨人协调劳动是后续扩展目标，不阻塞首个个人可用版本。

## 2. 端到端用户体验

### UX-01：首次进入与环境准备

用户不应被要求先理解容器、运行时和消息队列。

最小流程：登录 → 连接指定仓库 → 选择或确认运行环境 → 设置资源上限 → 验证通知渠道 → 开始委派。

- 只申请所选仓库的必要权限。首发默认读取仓库、在云端工作空间修改；推送权限不默认申请。
- 展示会上传或读取哪些内容、云端保存位置类别、保留政策和费用承担方式。
- 环境预检检查仓库可访问、执行环境可启动、模型可调用、通知可测试。错误告诉用户下一步，不只显示堆栈。
- 缺少工具链、网络访问或测试配置时，明确限制；不能把“已连接仓库”显示成“所有任务都能完成”。
- 首发可只支持有限环境模板，并公开支持范围。不支持的环境在执行前说明。

验收：试用者依据界面独立完成一次配置，无需维护人员登录其机器代配。记录放弃点、错误类型和求助次数。

### UX-02：委派工作

主入口是目标描述，而不是基础设施配置表。系统从描述中整理一张可编辑的任务卡：

| 字段 | 行为 |
| --- | --- |
| 目标 | 用户希望发生什么变化 |
| 输入 | 仓库、分支和固定 commit；附件显示上传完成状态 |
| 交付物 | 默认补丁、变更摘要、测试证据；不默认推送 |
| 验收条件 | 用户指定条件与系统补充建议明确区分 |
| 授权 | 可读写范围、可运行工具、允许外联目的、需单次审批的操作 |
| 限额 | 执行时间、模型用量/费用约束、存储；注明估算和硬限制的区别 |
| 阻塞规则 | 默认等待用户，不超范围猜测或扩大权限 |

对会改变目标或权限的歧义，执行前集中澄清；不要求用户预先回答所有实现细节。

提交后：

1. 输入未上传完成时显示“上传中，请保持连接”，不允许声称可以离场。
2. 云端持久保存输入引用、目标、授权版本和任务后，返回稳定任务 ID。
3. 此时显示“已在云端接收，可以关闭此设备”；准备环境和排队可以在用户离场后继续。
4. 提交响应丢失时，客户端按同一请求标识查询或重试，不创建第二个任务。

示例文案：“已在云端接收。完成或需要你决定时会通知你。当前任务不会自动推送代码。”

### UX-03：查看工作，而不是盯守终端

首页默认显示工作事项，不以 bot 列表或 token 流为中心：

- 需要我处理：待决策、凭据问题、需人工核查的异常。
- 正在进行：排队、准备、执行、恢复中的工作。
- 等待验收：已交付结果与证据。
- 历史：已验收、失败、取消或归档的工作。

任务详情第一屏回答：正在做什么、已经产出什么、是否受阻、是否需要我、消耗多少、怎么停止。

- 使用“正在准备环境 / 正在修改 / 正在验证”等实际阶段，不生成无依据的百分比和完成时间。
- 显示最近状态更新时间；连接中断时标记“当前显示为缓存状态”，不把旧内容当实时进度。
- 实时工具流和日志可以展开，但用户不读它们也能理解任务。
- 跨设备查看同一份云端状态，不依赖旧设备同步本地聊天文件。

### UX-04：必要决策与离线通知

通知分为待决策、需行动的异常和交付就绪三类；普通执行步骤默认不推送。

决策卡必须包含：

- 受阻原因和影响范围。
- 可选动作、推荐选项及理由。
- 是否增加费用、权限或对外副作用。
- 不回复时的行为、有效期与当前状态。

默认无回复就等待；允许继续独立工作的策略必须预先授权。不要通过宽泛的“始终允许”消除所有安全确认。

审批绑定任务、操作内容摘要、目标资源、授权版本和有效期。内容或目标改变后原审批失效。通知链接只负责导航，打开后重新认证和授权，不能靠访问一个链接直接执行审批。

示例：“测试需要访问新增依赖源，当前未授权。允许本任务访问该域名 / 保持暂停。未回复时不会继续安装。”

- 同一待决策事项只创建一张卡，重复投递不得生成多个可执行审批。
- 初始提醒策略：首次通知一次；24 小时仍未处理可提醒一次，此后进入摘要，不持续催促。
- 静默时段推迟非紧急推送，不改变任务安全状态；安全告警是否例外须由用户配置。
- 通知渠道失败在工作台可见；渠道接受、实际送达、用户已读分别记录，未知时不显示“已送达”。

### UX-05：补充、暂停与取消

补充说明保存为有版本的任务输入。若改变当前执行目标，在安全边界暂停并确认新范围，不能静默修改已批准的外部操作。

- 暂停：停止调度新动作，在安全边界保存进度，之后可以创建新的执行尝试继续。
- 取消：停止该任务的后续执行，保留已有结果与副作用记录；再次工作需显式重试或创建后续任务。
- 撤销授权：立即阻止尚未开始的受影响动作；已发出的远程请求可能仍完成，需核查并报告。
- 控制面收到停止请求后先显示“正在停止”，执行环境确认停止后才能显示“已停止”。

对于失联执行环境，不能把“取消请求已记录”当成“进程已经退出”。展示“停止待确认”，阻止新的外部授权并持续核查。

### UX-06：验收与交付

交付包至少包括：目标对照摘要、输入 commit、补丁/文件、运行的测试与结果、未验证事项、已发生外部操作、用量摘要。

- 产物按版本保存；有校验信息，能下载，在承诺保留期内不随 worker 回收而消失。
- 测试未运行、运行失败和通过明确区分。模型自述不能替代测试证据。
- 用户可以验收通过、提出修改、下载结果或归档。
- 提出修改生成关联的后续任务，旧交付保持不变；来源分支已经变化时，不覆盖用户的当前分支。
- 推送/创建 PR 若后续支持，使用独立明确授权，不与“验收通过”隐式绑定。

### UX-07：错误与恢复

| 情况 | 用户看到什么 | 系统行为 |
| --- | --- | --- |
| 本机断网 | 连接已断开，云端工作继续；显示最后更新时间 | 重连取快照并补事件，不重发任务 |
| 环境启动失败 | 原因分类、已消耗资源、重试或取消入口 | 有界重试；不会无限开新环境 |
| 模型限流或服务故障 | 正在重试或等待服务恢复 | 按预算重试，达到上限后等待/失败 |
| 凭据失效 | 需要重新授权 | 暂停相关动作，不向用户索取明文密钥聊天消息 |
| Worker 失联 | 正在核查执行状态 | 撤销旧租约、阻止双重执行；未知副作用不盲目重试 |
| 预算不足 | 已保存哪些结果，继续需要增加什么限额 | 不再启动超额动作，保留可下载产物 |
| 通知失败 | 渠道异常，但任务和决策仍在 | 持久化重试与工作台补偿展示 |

## 3. 领域契约与状态一致性

以下是逻辑契约，不锁定数据库或接口实现。

| 对象 | 必要含义 |
| --- | --- |
| Task | 用户目标、输入快照、授权/预算版本、当前状态与稳定 ID |
| Run | 一次执行尝试及租约；重试新增 Run，不覆盖前一次记录 |
| Workspace | 可恢复工作数据与受限执行环境的关联；隔离用户和并发修改 |
| Approval | 一次明确决策及绑定操作、有效期、批准人、消费记录 |
| Artifact | 不可变交付版本、来源 Run、摘要、校验与保留期限 |
| Event | 持久化事实、任务内顺序号、发生时间与关联 ID |
| Notification | 来源事件、渠道、去重键、投递状态，不替代业务状态 |

### 3.1 任务状态

主路径：`已接收 → 准备中 → 执行中 → 交付就绪`。容量不足时进入排队；阻塞可进入待决策、待恢复或已暂停；终止可为失败或已取消。

“正在停止”是控制请求状态，“已验收”是交付验收状态，不与执行状态混成一个布尔值。

关键规则：

1. 已接收意味着持久化成功，不能只把请求放入内存。
2. 状态变更和待发送事件须可一致恢复，不能出现状态保存了但通知永久丢失。
3. 同一任务默认只有一个有效执行租约；旧 worker 即使恢复也不能继续凭旧授权执行外部动作。
4. 审批与取消并发时，操作启动前再次检查有效授权；取消之后不得消费旧审批开启新动作。
5. 重连先获取带版本快照，再补事件；重复或乱序事件不使界面倒退，缺口通过补拉修复。
6. 终态不由旧事件重新打开；继续工作创建明确的新执行尝试或后续任务。

## 4. 技术指标与测量口径

### 4.1 指标边界

所有目标面向首个受控试点，不是当前实测结论。测量必须记录版本、部署配置、时间窗口、请求总数、错误数和样本分布。

初始容量包络建议：10 个试点账号、全局 5 个并发执行任务、20 个在线查看连接；每任务执行资源上限建议 2 vCPU / 4 GiB 内存 / 10 GiB 可写磁盘。支持的任务不得依赖 GPU 或超出此包络的构建。以上作为首轮压测输入，选定云环境后复核，不作为永久产品套餐。

平台控制面指标与模型、仓库、通知供应商耗时分开统计，同时保留端到端数据；不得通过剔除供应商失败美化用户实际成功率。

### 4.2 交互与控制面目标

| 编号 | 初始目标 | 测量方式及边界 |
| --- | --- | --- |
| T01 接收响应 | p95 ≤ 2 秒 | 输入已就绪的提交请求到返回持久化任务 ID；不含附件上传，但含事务提交 |
| T02 状态查询 | p95 ≤ 1 秒 | 在容量包络内的任务列表/详情 API，包含鉴权；错误另计 |
| T03 跨设备刷新 | p95 ≤ 5 秒 | 状态持久提交到健康客户端可见；断线后从重连成功起计 |
| T04 排队调度 | p95 ≤ 10 秒 | 有可用配额与健康 worker 时，已接收到租约分配；冷启动和资源不足单列 |
| T05 停止反馈 | p95 ≤ 2 秒 | 停止请求到持久化确认，不等于执行已经停止 |
| T06 云端 sandbox 停止 | p95 ≤ 30 秒 | 控制请求确认到受控 sandbox 进程组退出；先优雅停止，必要时终止，保存已有产物 |
| T07 冷环境准备 | p95 ≤ 120 秒 | 使用已声明的标准镜像、小型测试仓库、依赖缓存条件；不含模型执行，不外推到任意仓库 |

T06 不承诺撤回已提交的外部 API 动作；必须单列其结果为已完成、失败或待核查。对指标超时展示具体状态，而不是无限 loading。

UI 不设模型首 token 硬门槛，也不承诺任意任务完成时长。提交后及时返回可靠状态比伪造进度更重要。

### 4.3 可靠性、调度与通知目标

| 编号 | 初始目标 | 测量方式及边界 |
| --- | --- | --- |
| R01 控制面可用性 | 连续 30 天 ≥ 99.5% | 每分钟从外部探测认证后的查询与合成写入；计划维护也计入，不等同模型任务成功率 |
| R02 已接收任务完整性 | 故障验收中丢失为 0 | 在声明的单进程/单 worker/单节点故障域内验证；磁盘灾难单独使用 R05 |
| R03 失联检测 | ≤ 60 秒 | worker 心跳消失到显示待恢复；不能仅靠无 token 判断失联 |
| R04 安全恢复 | p95 ≤ 5 分钟 | 替代容量健康且依赖可用后，进入可执行恢复或明确人工核查；不是恢复任意进程现场 |
| R05 灾难恢复 | RPO ≤ 15 分钟，RTO ≤ 4 小时 | 持久层整体丢失的备份演练目标；RPO 内可能丢失的数据不得宣传为零丢失 |
| R06 通知排出 | p95 ≤ 60 秒 | 可推送事件提交到首次向健康渠道发送；静默期另列 |
| R07 通知失败处置 | 24 小时内有界重试 | 指数退避与去重；耗尽后标记失败，工作台保留事项，不保证第三方实际送达 |
| R08 长期触发偏差 | p95 ≤ 60 秒 | 后续启用计划功能时，健康调度器的计划时间到任务持久创建；不含等待执行资源 |

恢复故障域必须写入发布说明。首发若达不到单节点恢复或灾难指标，应明确降为内部验证，不以模糊“支持恢复”替代。

### 4.4 用量、预算与资源

- 每任务强制设置最大执行时间、模型请求/输出上限及环境配额；初始建议单次活跃执行上限 60 分钟，可在执行前显式调整。
- 模型与云资源分别记账；缺少供应商数据时显示“未知/估算”，不能按零计算。
- 金额硬上限只有在每次请求前能预留最坏情况费用时才承诺。否则采用可执行的 token/请求/时间限额，并明确金额只是估算。
- 预算不足不启动下一动作；在途调用可能产生已预留费用，禁止用统计延迟后的余额冒充严格限额。
- 等待审批时停止新的模型调用；持久保存后，空闲执行环境目标在 10 分钟内回收或挂起。不能安全保存时明确报告额外费用与处置选项。
- 并发和配额耗尽进入排队或可解释拒绝，不静默创建超额资源。
- 任务停止后的资源回收目标 ≤ 5 分钟，保留数据与运行资源分开核算。

### 4.5 数据与安全

以下为发布底线，不以百分位目标豁免：

- 所有任务、事件流、产物、审批、下载都执行服务端身份与资源归属校验；跨账号测试必须拒绝访问。
- 不同账号不共享可读写工作空间、浏览器会话或明文凭据；任务隔离与网络出口限制在执行层实现。
- 不可信任务不能访问云元数据、控制面管理接口或无授权的内网服务；安装依赖同样属于不可信代码执行。
- 凭据通过秘密存储和受限注入提供，不写入 prompt、日志、交付物或普通数据库字段；下载链接有短有效期且不得泄露敏感内容。
- 通知正文默认不包含代码、密钥或敏感仓库细节；详情通过鉴权入口访问。
- 用户上传数据传输和静态存储加密；明确服务使用的模型与第三方数据处理边界。
- 所有授权、审批、外部副作用、取消和删除可审计；内部诊断也不能默认记录原始 prompt 与代码。

建议初始数据政策：任务记录及交付物保留 30 天，凭据仅保留至撤销或授权到期，备份滚动保留不超过 30 天；最终需在试点前确认并展示。

删除请求先禁止访问与新执行，核查在途执行后清除活动数据，目标 24 小时内完成。备份按公布周期淘汰；从备份恢复必须重放删除标记，不能让已删数据重新可访问。依法或安全审计需要保留的最小记录必须明确披露，不保留任务正文作为默认例外。

### 4.6 界面可用性

- 核心流程支持桌面和宽度 360px 的移动浏览器，无横向滚动依赖；代码 diff 可提供独立滚动区。
- 键盘可完成委派、查看、审批和取消；焦点清晰，状态不只依赖颜色。
- 断线、空列表、无权限、加载失败都有明确状态和恢复入口。
- 通知跳转后即使会话已失效，也能在登录后回到原事项，不丢失待处理目标。
- UI 视觉设计若复用 VCoder 工作台，遵循其视觉母版与漂移检查流程；本文只规定行为，不替代视觉设计。

## 5. 从验证到可用的发布门槛

阶段与半年规划对应，但不是按月份自动放行。未达标保持当前发布级别。

| 级别 | 用户范围 | 必须满足 |
| --- | --- | --- |
| V0 云端闭环验证 | 开发者内部 | UX-01/02/03/06 主路径；已接收后关机仍交付；鉴权与隔离基础；明确当前恢复限制 |
| V1 可离场内测 | 邀请用户 | UX-04/05/07；跨设备通知审批；预算与停止；故障矩阵通过；核心控制面指标通过压测 |
| V2 受控可用版本 | 限定试点容量 | 全部适用契约；30 天运行观测；备份/删除演练；用户收益证据；无未解决发布阻断问题 |

R08 及长期职责仅在该功能开放时适用。多 bot、自动化数量和模型数量不参与升级判定。

### 5.1 基准与用户收益验证

建立至少 30 个固定任务，覆盖小型变更、测试修复、纯调查、环境失败、必要审批与恶意输入。标记每项的可验收结果与预期人工决策。对随机性任务重复测试，报告样本数与波动，不用单次演示判定通过。

对照本地 VCoder + 同一模型/skills、同一仓库快照和等价授权；区分执行内核变化与云端产品带来的收益。

V2 初始准入建议：

- 至少 5 位非实现者试用，累计至少 50 项任务，保留失败与主动放弃样本。
- 信息齐备且无预设人工决策的固定任务中，至少 80% 无需中途补指令而交付；同时单独报告结果验收率，不能用“没打扰”掩盖错误。
- 对照任务集的验收通过率不得低于本地基线超过 5 个百分点；小样本结论只用于内测，不作为泛化宣传。
- 中途人工介入次数中位数较基线降低至少 50%；基线为零的任务只检查不增加，不计算无意义的降幅。
- 所有发起设备离线验收任务均不得因客户端断线而中止；模型或外部故障单列，仍计入端到端结果。
- 试用者能够自行取回交付、理解阻塞、停止任务；通过任务观察与访谈记录，不仅依赖满意度打分。

这些比例是可用性假设，首轮试用后按证据复核。调整时记录原值、数据、原因与风险，不能在发布前为过门槛临时删除失败样本或降低安全标准。

### 5.2 故障与风险验收矩阵

| 编号 | 注入场景 | 必须成立的结果 |
| --- | --- | --- |
| A01 | 接收响应丢失后重复提交 | 同请求只对应一个任务，可查询真实接收状态 |
| A02 | 确认接收后发起设备关机 | 云端继续；另一设备可见结果 |
| A03 | 任务准备/执行中终止 worker | 不丢任务；旧租约失效；恢复或明确等待核查 |
| A04 | 外部操作成功但回执保存前崩溃 | 不盲目重复；使用可核查证据或人工确认 |
| A05 | 审批期间重启控制服务 | 决策卡保留，内容一致，审批只能有效消费一次 |
| A06 | 两设备分别批准和取消 | 不启动取消后禁止的新动作；竞态结果可审计 |
| A07 | 预算耗尽、超时、失联 | 不新增超额动作；部分产物可取回；停止状态真实 |
| A08 | 事件重复、乱序和长时间断线 | 快照与事件收敛，不倒退或丢失决策 |
| A09 | 通知供应商持续失败 | 有界重试；工作台可处理；不伪报已送达 |
| A10 | 仓库文件/网页要求读取密钥或内网 | 执行层拒绝越权；不把输入内容当授权 |
| A11 | 猜测另一账号任务/产物/事件 ID | 服务端拒绝，不能通过流式或下载旁路泄露 |
| A12 | 删除后执行备份恢复 | 已删除内容不重新开放，凭据不复活 |
| A13 | 来源分支改变、同仓库并发任务 | 不覆盖用户变更，交付来源与冲突清楚可见 |
| A14 | 超出并发容量、依赖供应商限流 | 可解释排队/拒绝/等待，无无限重试或资源增长 |

安全与控制竞态场景在每个发布候选执行；失败阻断发布。故障测试通过不等于证明零风险，试点仍需审计和事故响应。

## 6. 开发拆分与完成标准

按垂直用户旅程开发，避免先造完整平台再寻找场景。

| 工作包 | 依赖 | 交付和主要验收 |
| --- | --- | --- |
| W1 云端接收与输入快照 | 部署、身份与数据政策决定 | UX-01/02、T01、A01/A02 |
| W2 隔离执行与产物 | W1、VCoder runtime 适配 | UX-03/06、T04/T07、A10/A11/A13 |
| W3 跨设备状态与控制 | W1/W2 | UX-03/05、T02/T03/T05/T06、A06/A08 |
| W4 决策与通知 | W3、通知渠道选择 | UX-04、R06/R07、A05/A09 |
| W5 恢复、预算与生命周期 | 从 W1 起建设，W2—W4 集成 | UX-07、R02—R05、A03/A04/A07/A12/A14 |
| W6 可用性与发布验收 | 前述工作包 | 压测、30 天观测、真实试用、升级/恢复与数据删除 |

每个工作包完成必须具备：对应用户界面及失败状态、服务端授权、自动化测试、相关故障用例、测量事件和指标说明、运维处理入口。只完成成功路径不算完成。

事件关联至少贯通账号、taskId、runId、操作 ID、审批 ID 与通知 ID；只记录诊断所需的最小信息，不把原始代码写进指标标签。

发布阻断问题包括：用户间数据泄露、授权绕过、已接收任务静默丢失、危险操作重复执行、取消状态误报、无预算约束、交付物不可取回，以及无法完成承诺的删除。
