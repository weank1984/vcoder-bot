# vbot 桌面后台任务首轮接入

日期：2026-09-20。范围：现有 Grok Bot 桌面入口接入验证服务，沿用其任务、停止和交付 API。

## 如何试用

试用包：`dist/VBot Background Tasks.app`。界面验收使用先前的 `VBot Background Tasks Preview.app`；最终试用包补充了无效服务响应的错误脱敏。尚未提交或推送本轮改动。

1. 打开预览包，点击“后台任务”。服务连接填 `http://127.0.0.1:18791` 和当前验证服务访问令牌。令牌不是 DeepSeek API key；后端继续使用已配置的 `deepseek-flash`。
2. 在已登录的 bot 对话输入区输入目标，点击“委派后台任务”，把目标带入确认面板。也可以从“后台任务”入口直接填写。
3. 确认仓库 URL、完整 commit、目标、逐条验收条件和最长分钟数，再点“确认并委派”。仅发送确认面板中的信息，不上传附件或整段聊天记录。
4. 查看服务确认接收的任务 ID。关闭面板或 App 后，服务独立运行；本机部署必须保持电脑、服务和 Docker 在线。
5. 重新打开 App 的“后台任务”，从服务取回任务状态及摘要、测试结果、用量，下载 patch 或其他交付物。当前列表展示服务最近 100 项；上次选中的任务按 ID 重新查询。
6. 运行中可点“停止后续执行”。等待服务确认退出前显示“正在停止”。

可用 [首轮试用流程](VALIDATION-USER-TRIAL.md) 中的固定仓库和任务内容。

## 本轮实现

- 桌面主进程负责 HTTP 访问；通过 `appWindow` 信任检查的 RPC 暴露固定操作，renderer 不直接持有服务令牌。
- 凭据使用现有系统安全存储。系统安全存储不可用时仅保留本次会话，界面提示重新连接。
- 连接时检查兼容服务及鉴权；远端要求 HTTPS，HTTP 仅允许 loopback；拒绝重定向。
- 提交前持久保存请求 ID 和任务输入；网络失败后同一内容重试复用 ID，避免重复创建。草稿和选择按服务地址隔离保存。
- 展示当前状态、更新时间和断连过期提示。`delivered` 显示“已交付 · 待验收”，明确交付不等于验收通过。
- 下载前检查交付物属于当前任务并验证 SHA-256；响应读取限制 10 MiB。
- 生产构建把任务面板代码并入现有原版 renderer 扩展，其哈希进入 `renderer-router-extension.json`，保留原有文件清单校验。

## 验证与限制

完整项目检查 37/37 通过，包含前后端类型检查、服务客户端回归和真实本机 HTTP 集成：配置验证、密钥不回传、错误不泄漏凭据、重复提交去重、重新创建客户端后查询、交付归属与哈希、停止请求状态。预览包通过 macOS ad-hoc 签名和项目打包校验，实际 App 已显示“后台任务”入口、连接表单和委派面板。

图形控制在连接操作期间丢失状态，未确认实际 UI 提交、下载、App 重开后的完整点击流程。预览 App 当前显示登录页，已登录对话中的草稿带入仍需实际试用；不得把 HTTP 回归算作全部交互验收通过。

这是桌面任务面板的首轮接入，尚未将任务卡插入聊天历史或按 bot 分组；会话输入区提供委派入口，任务记录以服务为准。尚无阻塞补充后续跑、系统完成通知或自动拉起后台服务。

后端当前只预授权 `git diff --check`。页面所展示的测试证据来自服务交付，额外独立验收结果尚未自动回写。已有缺少输入的任务可能以交付摘要结束，仍需读摘要判断目标是否完成。实际云主机离场与跨物理设备取回仍待验证。
